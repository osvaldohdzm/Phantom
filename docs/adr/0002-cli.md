# ADR 0002: Consolidación y Rediseño del CLI phantom

* **Estado:** Aprobado
* **Fecha:** 2026-07-28
* **Autor:** Antigravity (Software Architect)

## Contexto

El script `./phantom` en la raíz del repositorio centraliza toda la operación del proyecto. Sin embargo, su estructura original dependía de comandos planos y flags globales que mezclaban la ejecución nativa con la ejecución Docker de forma ambigua. Al agregar requerimientos de mantenimiento como respaldos, gestión de plugins, generación y servicio de documentación, y diagnóstico de salud, el CLI plano se volvía complejo de extender sin colisionar con nombres de comandos existentes.

## Decisión

Hemos decidido migrar el CLI `phantom` hacia una arquitectura basada en **Namespaces Operacionales**. Esto organiza las llamadas en un patrón jerárquico claro:

`./phantom <namespace> <subcomando> [ambiente] [opciones]`

### Namespaces e Interfaces Implementadas

- **`local`**: Start, stop, restart, dev, prod, install, uninstall, clean, debug, sbom, passwd. Centraliza el ciclo de vida nativo del host.
- **`docker`**: Build, start, stop, restart, status, logs, fix. Encapsula Docker Compose delegando a `deploy/docker/docker-compose.yml`.
- **`cluster`**: Deploy, destroy. Genera manifiestos e interactúa con clusters de Kubernetes (`kubectl`).
- **`docs`**: Generate, serve. Gestiona el portal Docsify local.
- **`plugin`**: List, install. Punto de extensión para dependencias externas y scripts.
- **`doctor`**: Comando de diagnóstico integral que verifica .env, dependencias de sistema (Python, Node, npm, Docker, mkcert), disponibilidad de puertos (3000, 8000) y validez de certificados TLS.
- **`backup` / `restore`**: Snapshots unificados de PostgreSQL y volúmenes de almacenamiento.
- **`migrate` / `release` / `update` / `version`**: Utilidades cruzadas del ciclo de vida.

### Mitigación de Cambios Incompatibles

Para evitar romper el flujo de trabajo existente del equipo y la automatización en scripts (e.g. `Makefile`), el script `phantom` incluye un enrutador de compatibilidad hacia atrás. Si se ejecuta un comando antiguo directo como `./phantom start dev`, el enrutador lo intercepta e invoca transparentemente su contraparte namespaced (e.g. `./phantom local start dev`).

## Consecuencias

### Positivas
- **Extensibilidad:** Añadir nuevos comandos o dominios operativos (como Helm, Terraform o pipelines CI/CD) ahora se reduce a crear un namespace o subcomando sin riesgo de colisión.
- **Experiencia de Desarrollador (DX):** El comando `./phantom doctor` permite a cualquier desarrollador que clona el repo identificar qué le falta en su entorno en segundos.
- **Consistencia:** El `Makefile` y la documentación se sincronizan con una única interfaz estructurada.

### Negativas / Riesgos
- **Complejidad del Script:** El script de bash de `phantom` ha crecido en lógica de enrutamiento, requiriendo un control estricto de los argumentos (`shift`) y validación de sintaxis (`bash -n phantom`).
